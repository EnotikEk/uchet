# Переход на PostgreSQL — инструкция для сервера

Приложение теперь работает с PostgreSQL вместо SQLite-файла `db.db`. Ниже — что сделать на продакшен-сервере (Linux, там же, где запущены gunicorn/nginx), и отдельно — как смотреть данные в базе без самого приложения.

Всё ниже выполняется **вами на сервере** — у меня нет доступа к нему.

## 1. Установка PostgreSQL (нативно, через apt)

```bash
sudo apt update
sudo apt install -y postgresql postgresql-contrib
sudo systemctl enable --now postgresql
```

## 2. Создание базы и пользователя

```bash
sudo -u postgres psql
```

В открывшемся `psql`:

```sql
CREATE USER uchet WITH PASSWORD 'придумайте-надёжный-пароль';
CREATE DATABASE uchet OWNER uchet;
\q
```

По умолчанию PostgreSQL слушает только `localhost` — этого достаточно, т.к. приложение и БД на одном сервере. Открывать порт 5432 наружу не нужно (см. раздел 6 про удалённый просмотр через SSH-туннель).

## 3. Переменные окружения для приложения

Приложение и `migrate_data_to_postgres.py` читают одну из двух схем настройки (см. `get_db_config()` в `database.py`):

- **`DATABASE_URL`** целиком, например:
  ```
  DATABASE_URL=postgresql://uchet:придумайте-надёжный-пароль@localhost:5432/uchet
  ```
- либо по отдельности: `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`.

Если не задать ничего, используются значения по умолчанию для локальной разработки (`localhost`/`uchet`/`uchet`/`uchet`) — **на проде обязательно задайте `DATABASE_URL` с реальным паролем**, дефолты для этого не годятся.

Добавьте переменную туда же, где сейчас настроен запуск gunicorn (systemd unit — блок `[Service]` → `Environment=`, либо файл, который вы `source`-ите перед стартом, либо `EnvironmentFile=`). Пример для systemd unit:

```ini
[Service]
Environment=DATABASE_URL=postgresql://uchet:придумайте-надёжный-пароль@localhost:5432/uchet
```

После правки:

```bash
sudo systemctl daemon-reload
```

(gunicorn пока не перезапускайте — сначала перенесите данные, шаг 5).

## 4. Установка зависимостей

В виртуальном окружении проекта на сервере:

```bash
source venv/bin/activate
pip install -r requirements.txt
```

Добавился пакет `psycopg2-binary` — он не требует компилятора и системных библиотек PostgreSQL для сборки.

## 5. Перенос данных из SQLite

Схема создаётся автоматически при старте `app.py` (в нём есть код, который сам вызывает `init_db()`/`upgrade_db()` при запуске). Но проще и безопаснее создать её отдельно, один раз, ещё до переноса данных и до первого запуска самого приложения:

```bash
DATABASE_URL=postgresql://uchet:пароль@localhost:5432/uchet python database.py
```

(запуск `database.py` как скрипта — а не просто `import database` — вызывает `init_db()` напрямую)

Затем перенесите данные из текущего файла (используйте копию, не трогайте `db.db`, которым ещё пользуется работающее приложение):

```bash
cp db.db db.db.backup_before_postgres
DATABASE_URL=postgresql://uchet:пароль@localhost:5432/uchet python migrate_data_to_postgres.py db.db.backup_before_postgres
```

Скрипт выведет количество перенесённых строк по каждой таблице и сверку количества строк источник/приёмник в конце — убедитесь, что везде `OK`, прежде чем идти дальше.

## 6. Перезапуск приложения

```bash
sudo systemctl restart <имя-вашего-systemd-юнита-gunicorn>
```

Проверьте логи (`journalctl -u <юнит> -f`) и откройте приложение в браузере — переключение филиалов, картриджи, оборудование должны работать как раньше, но уже на PostgreSQL.

`db.db` и `db.db.backup_before_postgres` не удаляйте — они нужны для отката (шаг 7) и как резервная копия.

## 7. Откат, если что-то пошло не так

Приложение проверяет `DATABASE_URL`/`PG*` при каждом запуске, но никакого кода для SQLite в нём больше нет — откат на предыдущую версию SQLite-кода означает откат кода приложения, а не просто переменной окружения. Поэтому план отката такой:

1. `git log` / посмотреть коммит перед переходом на PostgreSQL, сделать `git checkout <коммит>` (или восстановить предыдущую версию `app.py`/`database.py` из бэкапа/git).
2. Убедиться, что `db.db` на месте (не удалялся на шаге 6) — SQLite-версия кода сразу заработает с ним, т.к. в файл после перехода на PostgreSQL никто больше не писал.
3. Перезапустить gunicorn.

Если проблема не в самой БД, а в чём-то другом — можно откатить только переменные окружения (`DATABASE_URL`) не имеет смысла без отката кода, см. выше.

## Как смотреть данные в PostgreSQL не через приложение

### Вариант А — psql прямо на сервере (проще всего)

```bash
sudo -u postgres psql uchet
```

или под созданным пользователем `uchet`:

```bash
psql -h localhost -U uchet -d uchet
```

Полезные команды внутри `psql`:

```sql
\dt                          -- список таблиц
\d equipment                  -- структура таблицы (колонки, типы)
SELECT * FROM equipment LIMIT 20;
SELECT COUNT(*) FROM catrigs;
\q                            -- выход
```

Обратите внимание: все имена таблиц и колонок в этой БД хранятся в нижнем регистре (даже там, где в коде `app.py` они пишутся как `Equipment`/`Serial_number` — PostgreSQL сам сворачивает регистр непроквоченных идентификаторов). Поэтому в `psql` их нужно писать **без кавычек и в любом регистре** (`equipment`, `EQUIPMENT` — без разницы) — а вот в двойных кавычках с заглавными буквами (`"Equipment"`) PostgreSQL их, наоборот, **не найдёт**.

### Вариант Б — pgAdmin или DBeaver с вашего Windows-компьютера (через SSH-туннель)

Порт PostgreSQL (5432) на сервере наружу не открыт (см. шаг 2) — это осознанно, чтобы не светить БД в интернет. Подключаться нужно через SSH-туннель.

**Через встроенный клиент SSH (Windows 10/11) — прокинуть порт вручную:**

```powershell
ssh -L 5433:localhost:5432 ваш_пользователь@адрес_сервера
```

Оставьте это окно открытым, пока пользуетесь БД. Затем в pgAdmin/DBeaver подключайтесь к:
- Host: `localhost`
- Port: `5433`
- Database: `uchet`
- User: `uchet`
- Password: (тот, что задали на шаге 2)

**Через сам pgAdmin (без отдельного SSH-окна):**

При создании подключения (Register → Server) на вкладке **SSH Tunnel** включите "Use SSH tunneling" и укажите адрес сервера/логин/ключ или пароль SSH — pgAdmin сам поднимет туннель при подключении. На вкладке **Connection** укажите `localhost`/`5432` (это уже "с точки зрения" туннеля, т.е. как видно с сервера) и данные пользователя `uchet`.

**DBeaver** — аналогично: при создании соединения PostgreSQL есть вкладка **SSH**, где включается туннелирование с теми же параметрами (host сервера, логин, ключ/пароль), а на вкладке **Main** — `localhost:5432`, `uchet`/`uchet`.
